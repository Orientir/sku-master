# Публікація та автооновлення

## Перший запуск

Потрібен публічний GitHub-репозиторій з основною гілкою `main`. Увімкніть GitHub Actions і надішліть код разом із `.github/workflows/release.yml`. Додатковий сервер і персональні токени в програмі не потрібні: workflow використовує короткочасний `GITHUB_TOKEN` для публікації, а програма читає публічні релізи без авторизації.

Workflow бере номер версії з `Directory.Build.props`. Установщик містить адресу репозиторію, з якого виконано збірку. Перший установщик із GitHub потрібно встановити вручну: попередні локальні версії 1.0.0–1.0.8 не мали адреси оновлень.

## Наступні випуски

1. Змініть код і збільште `<Version>` у `Directory.Build.props`, наприклад з `1.0.9` на `1.0.10`.
2. Надішліть зміни в `main` або злийте перевірений pull request.
3. GitHub Actions запустить тести, збере Windows x64 установщик, portable ZIP і пакет оновлення.
4. Публікація спочатку створює чернетку, завантажує файли, перевіряє їхню наявність і розмір, а потім робить реліз публічним. Незавершена чернетка не пропонується користувачам як оновлення.

Наявний публічний номер версії не перезаписується. Зміни без збільшення версії проходять тести, але не створюють ще один реліз. Повторний запуск незавершеної публікації дозавантажує файли в чернетку. Нижчий номер не може замінити новішу версію як останню. Також можна надіслати тег `vX.Y.Z`, який має збігатися з версією у файлі, або запустити workflow вручну для `main`.

## Як оновлюється програма

Установлена програма перевіряє GitHub при запуску й завантажує новішу версію у фоні. Кнопка «Оновлення» встановлює завантажену версію після підтвердження перезапуску. Незбережений результат або поточна обробка блокують перезапуск. Portable-версія не має цього циклу встановлення. Файли товарів не передаються в GitHub.

Публікуйте разом усі згенеровані файли, зокрема `releases.win.json` і `SkuMaster-X.Y.Z-full.nupkg`. Повний пакет дозволяє оновлюватися без проміжних версій; генерація delta-пакетів поки не використовується.

## Перевірка після підключення репозиторію

Перевірте успішний Actions run і доступність файлів релізу без авторизації. Для повної перевірки встановіть перший GitHub-випуск, опублікуйте наступну версію й перевірте завантаження та перезапуск зі збереженням налаштувань. До виконання цього сценарію не вважайте цикл автооновлення перевіреним.

Джерела: [Velopack — GitHub Actions](https://docs.velopack.io/distributing/github-actions), [GitHub — керування релізами](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository?tool=cli).
